## 2026-11-27 决策：资产数据版本化与写入回读校验

- 背景：`.dsh-repowiki/` 的索引、卡片、Wiki、记忆都是随 Git 共享的普通
  文件。此前写入直接调用 `ctx.fs.writeText`，后端异常/中断可能留下截断的
  JSON 或 Markdown，而读取侧只能看到"解析失败"，无法区分"从未写过"与
  "写坏了"；同时索引新增 `module` / `modules[]` 后，旧索引缺少字段却仍以
  v2 版本号读取，契约边界不清晰。

- 选项 A：继续"写入即信任"，损坏时靠用户重跑工具。实现零成本，但静默
  损坏会扩散到 Git 历史，且诊断成本高。
- 选项 B：用"临时文件 + rename"做原子写。`ctx.fs` 没有 rename/move 原语，
  只能退回裸 node fs，违背"全部文件 IO 走 ctx.fs"的约束。
- 选项 C（选择）：写入后立即回读并逐字比较（`writeTextVerified`），不一致
  抛错；索引 schema 正式升到 v3，读取兼容 v2 并在内存补齐。

- 理由：回读校验能发现截断、编码替换与后端异常，且完全基于 `ctx.fs` 的
  readText/writeText，零新依赖；它不承诺原子性，但把"静默损坏"变成"显式
  失败"，让调用方可以重试或提示。schema v3 让新字段成为正式契约，同时
  通过 v2 兼容读取避免"升级必须重建"。

### 写入回读校验

- 位置：`src/util.js` `writeTextVerified(fs, target, text)`；`writeText` 后
  `readText` 比较，不一致抛 `write verification failed: <displayPath>`。
- 覆盖：`writeIndex`、`writeKnowledgeIndex`、`writeCard`、`writeWikiPage`、
  `writeMemory`、`setMemoryStatus`（以及清单写入）全部经该函数。
- 语义边界：**不是原子写**。进程在 writeText 中途崩溃仍可能留下半截文件；
  本机制只保证"函数返回成功即内容完整可读"。文档与 README 不声称原子性。

### 索引 schema v3

- `INDEX_SCHEMA_VERSION = 3`：`files[].module`、`modules[]`、`stats.modules`
  正式纳入契约。
- `readIndex` 接受 `INDEX_COMPATIBLE_VERSIONS = {2, 3}`：v2 文档在内存中
  通过 `buildModules(files)` 补齐 `module` 与 `modules`，读取方无需分支；
  未知版本返回 `null`，由工具给出"先重建索引"的提示。
- `repowiki-index` 始终写 v3；`repowiki-cards` 输出 `indexVersion` 方便诊断。

### 增补（v0.47.0）：索引 schema v4

- `INDEX_SCHEMA_VERSION = 4`：新增 `git: {branch, commit, shortCommit}`
  （只读 `.git/HEAD`，不执行 git 命令）与 `stats.languages`（语言分布）。
- `readIndex` 接受 `{2, 3, 4}`：v2/v3 在内存中补齐 `module`/`modules` 与
  `stats.languages`，磁盘版本号不变；下次 `repowiki-index` 写 v4。
- 读取侧对 `git` 字段保持可选：非 Git 仓库、worktree 解析失败或旧索引都
  不产生错误，面板/状态工具按"无 Git 信息"渲染。
- 测试：`test/git.test.js`（普通仓库/packed-refs/detached/worktree/异常 fs）、
  `test/indexer.test.js`（索引写入 git 与语言分布）、
  `test/status.test.js`（v4 与 Git 渲染）。

### 增补（v0.49.0）：索引 schema v5

- `INDEX_SCHEMA_VERSION = 5`：`edges[]` 新增 `line`（import/use/require
  语句行，1-based），支撑行号级反向引用。
- `readIndex` 接受 `{2, 3, 4, 5}`；旧边没有 `line` 时反向引用降级为
  仅路径（`referencedBy: [{path}]`），不报错、不伪造行号。
- 边上的 `line` 是语句起始行；同一语句导入多个符号只产生一条边，
  同一文件多次导入同一符号会保留多个引用位置。

### 影响与验证

- 影响范围：所有资产写入路径与索引读取路径；磁盘格式对 v2–v4 向后兼容，
  v5 为唯一写出格式。
- 测试：`test/write-verify.test.js`（截断写入必须抛错）、
  `test/assets.test.js`（v2 夹具读取补齐模块树、未知版本返回 null）、
  `test/indexer.test.js`（二次索引写 v4）。
- 回滚：删除 `writeTextVerified` 调用可回到直接写入；把
  `INDEX_SCHEMA_VERSION` 降回 2 并移除 v2 兼容分支即回到旧读取逻辑
  （已写出的 v3 文件仍含额外字段，旧读取器会忽略）。
