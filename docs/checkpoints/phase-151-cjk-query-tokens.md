# 检查点：中文查询只取双字组（phase-151）

- 日期：2026-11-28
- 合入版本：v0.175.0
- 目标：BM25 与面板搜索的查询分词与文档分词共用“单字 + 双字组”规则，
  导致多字中文查询被单字放大召回：查询“无匹配”会命中所有含“无”的卡片，
  真正相关的结果被噪声淹没。
- 状态：代码、测试、双语文档与检查点更新；待全量门禁与提交。

## 交付

- `src/search.js`：
  - 新增 `tokenizeQuery(text)`：拉丁词原样；CJK 连续段长度为 1 时保留
    单字；长度 ≥2 时只产出相邻双字组（不再产出单字）。
  - `rankDocuments` 的查询 token 改用 `tokenizeQuery`；`tokenize` 仍是
    文档侧分词（保留单字，保证“图”这类单字查询可命中）。
- `client.js`：`tokenizeClient` 与 `tokenizeQuery` 同构（仅用于面板查询
  打分），单字/拉丁行为不变。
- 测试：
  - `tokenizeQuery` 单元：`无匹配` → `['无匹','匹配']`、`索引` → `['索引']`、
    `图` → `['图']`、拉丁混合；空串为空。
  - BM25 夹具：正文只有“无序”的文档不再命中查询“无匹配”，含“匹配”的
    文档正常命中。

## 语义边界

- 只改查询侧：文档仍索引单字，因此“图”“云”等单字查询可用；也避免
  重建索引（索引指纹不含分词）。
- 双字组是 CJK 检索的常用折中：不做词典分词（零依赖、无词典），也不做
  整段短语匹配；多字查询仍可能因共享双字组而命中相近表述，但不再因
  单个虚词/常用字扩散。
- 拉丁词仍是完整 token 匹配（含下划线/数字），大小写不敏感；混合查询
  各段独立处理。
- 面板与 BM25 规则一致，但实现各自独立（浏览器包不引入宿主模块），
  注释互相指向，改动需同步。
