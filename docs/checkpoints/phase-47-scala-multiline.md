# 检查点：Scala 多行签名 v0.72.0（phase-47）

- 日期：2026-11-27
- 目标：Scala 3 / 惯用 Scala 常把参数逐行书写，函数体在 `) extends X {`
  或 `): T =` 之后才开始。旧实现只检查声明行是否含 `{` 或以 `=` 结尾，
  这类声明被记成单行符号，方法范围与成员归属错位。
- 状态：代码、测试、文档完成；本地全量验证通过；未提交/推送。

## 交付

- `src/symbols.js`：
  - 新增 `scalaHeaderTerminator`：从声明行向下扫描（上限 40 行），
    跟踪括号深度与字符串状态，返回顶层 `{` / `=` / `:` 终止符；
    `==`/`!=`/`<=`/`>=`/`=>` 与默认参数里的 `=` 不误判，参数类型里的
    `:` 因括号深度被忽略；
  - 续行判定：括号未闭合，或行尾为 `(`/`,`/`:`/`=`、`extends`/`with`/
    `implements` 时继续扫描；
  - 类型声明：`{` → 括号配平块；`:` → 缩进体；否则单行；
  - `def`：`{` → 括号配平块；`=` 后有内容 → 该行结束；`=` 后为空 →
    缩进体，且以**签名结束行**为缩进基准（修复多行参数后 body 被提前
    截断的问题）。
- 测试 `test/symbols.test.js`：多行构造参数 + `extends … {`、多行参数
  + 表达式块、多行参数 + 换行表达式体、顶层多行参数单行体，断言
  `endLine` 与 `parent`。
- 文档：两份 CHANGELOG、README 双语（stage/路线图）、
  `docs/compatibility.md`（Scala 行与已知限制）、`docs/coverage.md`。

## 关键决策与取舍

- 扫描上限 40 行：真实声明头极少超过十余行；上限避免未闭合声明吞掉
  后续文件内容。
- 只在括号深度 0 认结束符：`=`, `:`, `{` 在默认参数、类型标注、函数
  类型里都会出现，深度判断比正则逐行匹配可靠。
- 缩进体从签名结束行起算：`def f(\n …\n): T =` 的签名行与 `def` 行
  同缩进，但从 `def` 行开始扫描会把签名行误当成同级体结束；改从签名
  结束行起算即得到真实 body 范围。
- 宏展开、条件编译仍不解析（与其它语言一致），写入兼容矩阵。
