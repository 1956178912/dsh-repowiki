# 检查点：忽略规则字符类（phase-138）

- 日期：2026-11-27
- 合入版本：v0.162.0
- 目标：`src/ignore.js` 把 `[`/`]` 当作普通字符转义，`*.py[cod]`、
  `file[0-9].txt` 等 Git 常见规则完全不生效；兼容矩阵与模块注释还把它
  列为“有意不支持”。
- 状态：代码、忽略测试、双语文档与检查点更新；待全量门禁与提交。

## 交付

- `src/ignore.js` `globToRegex`：
  - 识别 `[abc]`、`[a-z]`、`[!a-z]`（转换为 `[^a-z]`）与 `[^a-z]`。
  - 未闭合 `[`、空类、含 `/` 的类按字面 `\[` 降级，避免跨路径段匹配。
  - 构造前用 `new RegExp` 验证；非法范围（如 `[z-a]`）按字面降级，
    不让一条坏规则中断整个索引。
  - 头部注释从“不支持字符类”改为“支持字符类”。
- `test/ignore.test.js`：新增正/负字符类、目录类与非法范围/未闭合降级。
- README 双语、覆盖率报告、CHANGELOG 同步。

## 语义边界

- 字符类不匹配 `/`：含斜杠的类直接按字面处理，保持“一段路径”约束。
- `[!...]` 与 `[^...]` 都表示否定；`[]`、`[abc` 等不完整形式按字面。
- 反斜杠转义仍不支持（与原有文档一致）；需要更复杂规则用 plan
  `exclude`。
- 嵌套规则的作用域逻辑不变，字符类同样受 `base` 约束。

## 取舍

- 不实现完整 POSIX 字符类（`[:alpha:]`）：Git 的常见用法是简单集合/范围，
  完整类会显著增加解析复杂度且很少出现在 .gitignore 中。
- 不为坏规则抛错：索引是只读诊断工具，跳过坏规则比整库失败更符合预期。
- 不改变 `RE_META` 的既有行为：字符类分支先于转义处理，其它元字符仍按
  字面处理。
