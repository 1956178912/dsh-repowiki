# 检查点：面板 GFM 表格与嵌套列表（phase-150）

- 日期：2026-11-28
- 合入版本：v0.174.0
- 目标：面板的零依赖 Markdown 渲染器只支持单层列表与段落。模型生成的
  卡片/Wiki 经常包含表格与缩进子列表，此前会被压成带 `|` 和 `-` 的普通
  段落，阅读体验与生成内容脱节；补上这两种主流形态是面板可读性的直接
  缺口。
- 状态：代码、测试、双语文档与检查点更新；待全量门禁与提交。

## 交付

- `client.js`：
  - 表格：`isTableDelimiter` 识别 `| --- | :--: |` 分隔行；`splitTableRow`
    支持 `\|` 转义与首尾竖线；`tableAlignment` 解析左/中/右对齐；渲染为
    `div[overflow-x:auto] > table > thead/tbody`，单元格参与既有行内格式
    （加粗/行内代码/链接），链接仍经 `safeHref` 白名单。
  - 列表：`parseListTree` 收集连续（可缩进）列表行（制表符按两空格），
    按缩进构建条目树；`renderListTree` 将相邻同类型条目合并为 `ul`/`ol`，
    子列表渲染在父 `li` 内，支持每层有序/无序混排。
  - 段落终止条件补充缩进列表标记，避免列表被吸进上一段；渲染器文档注释
    更新为“不支持图片/HTML 内嵌”。
- 测试：
  - 客户端卡片夹具新增两列表格（`| --- | :--: |`）、有序列表与缩进无序
    子项（措辞避开检索用例的查询 token）。
  - 新用例 `Markdown 渲染：GFM 表格与嵌套列表` 断言 `table` 节点、表头
    居中样式、`li > ul` 嵌套与 `ol` 混排。

## 语义边界

- 表格识别要求表头单元格数与分隔行一致，否则按普通段落处理（不猜测）；
  表格行以空行或其它块级起始结束，列数不齐时缺列补空、多列忽略。
- 对齐仅支持 GFM 的三种（缺省/`:` 左/`:` 右/双冒号居中），不允许自定义
  样式，避免模型输出影响主题令牌。
- 嵌套列表只按缩进表达层级（两个空格一层），不做“段落续行”合并；这与
  生成 prompt 产出的扁平/一层缩进结构匹配，超深缩进会正常嵌套但受
  React 渲染深度限制。
- 不引入任何第三方 Markdown 库，保持零运行时依赖；HTML 内嵌仍不渲染
  （安全与体积考虑）。
